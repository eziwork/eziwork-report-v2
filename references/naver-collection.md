# 네이버 공개 화면 수집 실행 절차

이 모듈의 네이버 경로는 Codex의 연결된 브라우저 도구로 실행한다. CLI가 별도 브라우저를 몰래 실행하거나 내부 API를 호출하지 않는다.

1. `preflight` 결과와 요청 대상·거래 유형·면적 조건을 확인한다. CUA에서 `getState`로 연결을 확인하고, 없으면 `BROWSER_REQUIRED`를 유지한다.
2. `https://fin.land.naver.com/`을 열고 대상의 이름과 주소를 대조한다. 동명이거나 식별이 불가능하면 `AMBIGUOUS_TARGET`으로 중단한다.
3. 요청한 거래 유형·면적·지역 필터를 적용하고, 실제 선택 상태를 다시 읽는다. 적용 불가/불일치는 `FILTER_MISMATCH`로 기록한다.
   필터 변경은 하나씩 수행하고 새 선택 상태를 확인한 뒤 다음 필터를 변경한다. 화면 전환 중 이전 DOM이 반환되면 현재 접근성 화면 또는 스크린샷으로 확인한다. 숨겨진 체크박스를 강제로 조작하거나 선택됐다고 추정하지 않는다.
4. 최대 20개 광고를 수집한다. 최신순 최대 12개, 가격순 최대 8개를 확인하고 광고번호 중복은 제거한다. 결과가 적으면 확인 가능한 개별 광고만 수집한다.
5. 그룹 카드를 개별 광고와 구분한다. 전체 표시수, 확인한 광고 수, 그룹 카드 수, 고유 광고번호 수를 각각 기록한다. 광고번호가 다른 광고를 동일 호실이라고 단정하지 않는다.
6. 상세 화면의 가격·면적·층 표기·확인일·거래 유형을 카드와 대조한다. 전용/공급/토지 면적을 구분하고, 공개되지 않은 주소나 층은 추정하지 않는다.
7. `scripts/collection/forms/S21.json`을 복사해 ACTUAL 자료를 작성한다. `identity.subject_id`, `observation.target_id`, 필터, 조회 시각, 표본 범위, 원문 링크와 화면 증거 파일을 채운다. 예시·비교 미완료 자료는 VERIFIED로 올리지 않는다.
   개별 광고에 `card_detail_match: true`를 기록한다. 화면에 선택된 전용면적을 `naver_filters.exclusive_area_sqm`으로 지정하면 정규화 면적과 자동 대조한다. 화면 증거는 스크린샷 또는 실제 읽은 화면 텍스트 발췌이며, 발췌를 스크린샷이라고 표시하지 않는다.
8. 화면 증거를 입력 파일과 함께 보관하고 개인정보를 검토한 뒤 `import --request request.json --run-id ... --file input.json --privacy-reviewed`로 연결한다. 반환 건수는 표본 광고 건수이며 시장 전체 물건 수가 아니다.

로그인·CAPTCHA·접근차단·호출 제한·화면 구조 변경은 각각 `LOGIN_REQUIRED`, `CAPTCHA`, `ACCESS_BLOCKED`, `RATE_LIMITED`, `UI_CHANGED`로 기록하고 중단한다. 같은 실행에서 실패를 숨기고 완전 수집으로 표시하지 않는다.

월세 광고는 `asking_price_krw`에 보증금을 기록하고 `deposit_krw`, `monthly_rent_krw`를 별도로 제공한다. 모든 날짜는 ISO 형식, 금액은 원, 면적은 m²로 변환하고 `area_type`에 EXCLUSIVE/SUPPLY/LAND/BUILDING 중 화면에 해당하는 종류를 남긴다. 원문 표기는 추가 필드로 보존한다.

공개 화면 수집 채택과 제공자의 재사용 허가는 별도다. 출처별 이용조건을 함께 기록한다.

기존 2026-10-08 점검에서는 공개 광고 한 건의 목록·상세 대조 및 공통 검증기 접수를 확인했다. 이번 배포 시험은 `scripts/collection/tests/fixtures/naver-input.json`의 저장 표본 재생이다. 현재 화면 재수집이나 최대 스무 건 표본 정책의 운영 검증 완료를 뜻하지 않는다. 수집 시에는 이용자가 연결한 현재 브라우저에서 다시 대조한다.
