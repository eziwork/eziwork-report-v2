# V안 공통 표지

완성 보고서는 **앞표지 → 기존 본문 → 끝표지** 순서로 출력한다. 사용자 선택 V안의 사선 건축 이미지, 청회색 제목, 노란 사선, 여백을 유지한다. 본문 스타일과 승인 문장은 표지 때문에 변경하지 않는다. 초안의 한 부분만 비교할 때는 표지를 강제하지 않는다.

`render`는 V 표지를 기본으로 추가한다. 계약 JSON의 `cover`에 짧은 대상명 `title`, 질문을 요약한 `subtitle`, `closing_title`, `closing_text`를 지정할 수 있다. 줄바꿈은 `\n`으로 지정한다. 숫자는 본문과 같이 검증된 `{{claim_id}}`로 연결한다. 날짜는 계약의 `basis_date`, 상담 정보는 branding 설정에서 가져온다. 예시의 대상·금액·날짜·아파트 입주 문구를 다른 유형에 복사하지 않는다.

```json
"cover": {
  "title": "잠실엘스와\n리센츠",
  "subtitle": "가격과 입주 조건을\n함께 비교해 보세요.",
  "closing_title": "궁금한 매물과\n조건을 말씀해 주세요.",
  "closing_text": "관심 있는 동·층과 희망 입주일을 알려주시면\n다음 상담에서 함께 살펴보겠습니다."
}
```

이는 아파트 비교의 문구 구조 예시다. 실제 대상일 때만 사용한다. 긴 대상명은 줄을 나누고, 제목이 너무 길면 대상 식별을 유지하면서 줄인다. PDF 검사는 텍스트 겹침·잘림을 오류로 처리한다. 연락처가 없으면 가짜 이름·전화번호·빈 입력란을 만들지 않는다. `business_name`, `contact_name`, `phone`에 사용자가 제공한 상담 정보를 입력한다. 로고는 기존 본문 헤더 설정을 유지하며 V 표지의 브랜드는 상호 텍스트로 표시한다.

맞춤 HTML에는 검증한 계약을 함께 전달한다. 상대경로 이미지를 보존하도록 같은 폴더의 새 파일명으로 저장한다.

```sh
python scripts/eziwork.py cover --input output/body.html --output output/report-v.html --contract output/report.json --branding config/branding.example.json
python scripts/eziwork.py pdf --input output/report-v.html --output output/report-v.pdf
```

`cover`는 검증 계약에서 표지 문구를 가져오며 맞춤 본문의 의미까지 자동 검증하지 않는다. 본문과 계약의 일치는 Codex가 대조한다. 이미 표지가 있는 파일에는 중복 추가하지 않는다. 사용자 요청으로 본문만 만들 때 계약의 `cover.enabled`를 `false`로 설정한다.

이미지는 직접 생성한 **추상 건축 장식**이다. 실제 매물 외관·조망·건축 상태의 근거가 아니다. 텍스트와 수치를 이미지에 생성하지 않는다. 과거 재생·합성 시험 문구는 앞표지에도 표시한다. 생성 결과는 이미지가 포함된 독립 HTML이며 배포 예시는 같은 패키지의 공용 이미지 파일을 참조한다.

인쇄는 `pdf` 명령을 사용한다. 표지는 A4 전체 면, 본문은 원래의 여백과 페이지 규칙으로 각각 렌더링한 뒤 합친다. 브라우저의 일반 인쇄는 원문 스타일에 따라 달라질 수 있다. Windows 검사와 실제 Mac 실행 확인은 구분한다.
